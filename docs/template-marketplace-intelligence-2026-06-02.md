## Helios Consultation

Helios should treat marketplace templates as pattern sources, not systems to adopt.

Decision gate for every template:

1. Does this improve decision quality, execution speed, or reliability?
2. Is the useful pattern already visible from the public preview?
3. Does the template contain private solo data that should stay out of shared systems?
4. Is the purchase under $5 and structurally useful enough to justify inspection?
5. Which agent owns the pattern after extraction?

Routing:

- Couples HQ / relationship structure -> Cupid, Hearth, Achilles.
- Shared money -> Midas + Achilles.
- Food, sleep, health, routines -> Vitalis + Achilles.
- Research/resource systems -> Atlas + Achilles.
- Business, startup, venture systems -> Vantage/Strategos, not Couples HQ.
- Career/job tracker -> Orion, not Couples HQ.
- Creative writing templates -> Kirin, not Couples HQ.
- Dark dashboard/aesthetic systems -> Forge + Achilles.

## Achilles Consultation

Achilles should not import templates wholesale. The useful move is a `Template Pattern Library` that captures reusable architecture:

- `Template`: title.
- `Source URL`: marketplace URL.
- `Cost`: free / paid amount.
- `Agent Owner`: Helios, Achilles, Midas, Vitalis, Atlas, Orion, Kirin, Forge, Strategos, Vantage.
- `Domain`: relationship, home, food, finance, health, business, career, creative, research.
- `Pattern Type`: dashboard, tracker, resource library, planner, habit loop, finance ledger, CRM, creative wiki.
- `Public Schema Available`: yes / partial / no.
- `Databases Observed`: names only.
- `Useful Fields`: fields worth reusing.
- `Views Worth Reusing`: calendars, boards, galleries, charts, quick-add buttons.
- `Privacy Risk`: low / medium / high.
- `Purchase Decision`: inspect publicly / buy under $5 / skip.
- `Integration Note`: exactly where the pattern belongs.

Achilles can then build from extracted patterns, not from copied template clutter.

## Integration Model for KNova / Helios

1. Create a local-first `Template Pattern Library` before any Notion build.
2. Store each template as a pattern card, not a duplicated system.
3. Let Helios approve pattern extraction based on decision quality, execution speed, and privacy.
4. Let Achilles translate approved patterns into Notion architecture.
5. Let domain agents own interpretation:
   - Midas: money templates.
   - Vitalis: food, health, sleep, fitness.
   - Atlas: resource libraries and research systems.
   - Orion: job trackers.
   - Kirin: creative dashboards.
   - Vantage/Strategos: business/startup systems.
   - Forge: aesthetic and UI rhythm.
6. Let Codex/Forge build extraction tooling only after repeated manual template analysis creates enough real friction.
