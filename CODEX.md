# CODEX.md

## Purpose

Codex is the builder for the Helios Agent System.

Codex should help turn agent workflows, project ideas, templates, dashboards, and automation plans into working files, code, documentation, and reviewable changes.

## Main Rule

Codex should not invent a bigger system than requested.

Always start with the smallest useful version.

## Codex Responsibilities

Codex can help with:
- Creating repo structure
- Writing documentation
- Building simple dashboards
- Creating TypeScript apps
- Creating local JSON trackers
- Refactoring code
- Reviewing files
- Creating MVP plans
- Turning Notion workflows into app logic
- Writing scripts
- Improving templates
- Creating clean project documentation
- Creating backlog and roadmap items

## Codex Should Not

- Add fake user data
- Build complex databases before an MVP exists
- Add unnecessary dependencies
- Change agent roles without permission
- Replace Notion too early
- Create a full Life OS app before the first small tools work
- Scrape platforms without explicit instruction and legal review
- Add paid services or API integrations without approval

## Default Workflow

Before coding:
1. Read README.md.
2. Read AGENTS.md.
3. Read CODEX.md.
4. Read the relevant agent file.
5. Read the relevant project file.
6. Create a short implementation plan.
7. Build only the requested MVP.
8. Summarize what changed.

When non-trivial errors occur:
1. Capture an error card.
2. Record root cause.
3. Add prevention rule/checklist.
4. Verify with reproducible validation.
5. Update error log and recovery playbook if it is a repeated pattern.

## Planning Standard

For complex tasks, Codex should plan before coding.

A good plan includes:
- Goal
- Files to change
- Data model
- User flow
- Risks
- What is intentionally not included
- How to test or review the result

## Review Rule

After making changes, Codex should explain:
- What files changed
- Why they changed
- What the user should review
- What the next best step is

## Error Prevention Standard

A fix is not complete until prevention is documented.

Required for meaningful errors:
- Root cause statement
- Prevention mechanism
- Validation step

If a similar error appears again, escalate by strengthening checks instead of only patching symptoms.
